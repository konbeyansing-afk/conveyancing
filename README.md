# Conveyancing Academy

Internal Learning Management System for training staff who support Australian conveyancing firms. Built as a modular, multi-program platform — QLD Conveyancing is the first program, with room to add NSW/VIC conveyancing, HR, IT, and other internal training programs later without a redesign.

See `AGENTS.md` (auto-generated by Next.js — leave it in place) for framework-specific notes.

## Stack

- Next.js 16 (App Router, TypeScript)
- Tailwind CSS + shadcn/ui
- PostgreSQL (Neon) via Prisma 7 (Neon driver adapter)
- Auth.js (NextAuth v5) — email/password credentials auth, role-based access (Admin/Trainer/Trainee)

## Setup

1. **Install dependencies**

   ```bash
   pnpm install
   ```

2. **Environment variables** — copy `.env.example` to `.env` and fill in:

   - `DATABASE_URL` — a PostgreSQL connection string (Neon: copy from your project dashboard, keep `?sslmode=require`).
   - `AUTH_SECRET` — generate with `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`.

3. **Run migrations**

   ```bash
   pnpm exec prisma migrate dev
   ```

4. **Seed the first admin user**

   ```bash
   pnpm exec prisma db seed
   ```

   This creates `admin@conveyancingacademy.local` / `ChangeMe123!` unless you set `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` env vars first. Change the password after first login (password-change UI isn't built yet — update it directly via Prisma Studio in the meantime: `pnpm exec prisma studio`).

5. **Run the dev server**

   ```bash
   pnpm dev
   ```

   Visit [http://localhost:3000](http://localhost:3000) — you'll be redirected to `/login`.

## Project structure

- `prisma/schema.prisma` — data model (User, Program, Course, Module, Lesson, Quiz, Enrollment, Progress, etc.)
- `src/auth.ts` — Auth.js configuration (Credentials provider, JWT session with `role`)
- `src/proxy.ts` — role-based route protection for `/admin`, `/trainer`, `/app` (Next.js 16 renamed the "middleware" file convention to "proxy")
- `src/app/login` — sign-in page
- `src/app/admin`, `src/app/trainer`, `src/app/app` — role-specific dashboards, each with its own sidebar nav (`src/components/nav/nav-config.ts`)

## Roles

- **Admin** (`/admin`) — manages programs, courses, and users.
- **Trainer** (`/trainer`) — monitors trainee progress and reviews assessments.
- **Trainee** (`/app`) — takes courses and tracks their own progress.

Roles are stored on `User.role` and enforced both in `src/middleware.ts` (route-level) and via the session (`role` on `session.user`).

## Troubleshooting

- **`UNABLE_TO_VERIFY_LEAF_SIGNATURE` / WebSocket TLS errors connecting to Neon**: some machines (often due to antivirus or corporate HTTPS-scanning software) intercept TLS with a certificate Node's bundled CA store doesn't trust, even though Windows' own certificate store does. `pnpm dev` / `pnpm start` already pass `NODE_OPTIONS=--use-system-ca` to work around this. If you run Prisma CLI or a standalone script directly (e.g. `pnpm exec prisma db seed`, `pnpm exec tsx some-script.ts`) and hit the same error, prefix it with `cross-env NODE_OPTIONS=--use-system-ca` or `$env:NODE_OPTIONS="--use-system-ca"` (PowerShell) first.
